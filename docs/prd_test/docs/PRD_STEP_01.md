# PRD STEP 01 — 코어 오목 시스템 + 난이도별 대국

> 선행 문서: `CLAUDE.md`, `docs/GAME_RULES.md`, `docs/VALIDATION_GUIDELINES.md`
> 이 단계에서는 **AI API를 사용하지 않는다.** (대국 AI는 로컬 엔진)

## 목표

브라우저에서 바로 즐길 수 있는 **완성도 있는 오목 대국 MVP**를 만든다.
AI 대전(하/중/상)과 2인 로컬 대전이 가능하고, 승패가 정확히 판정되며, 대국이 끝나면 **GameRecord(기보)** 가 만들어진다. 이 기보가 2단계(복기)의 입력이 된다.

## 범위

| 포함 (In) | 제외 (Out) — 이후 단계 |
|---|---|
| 15×15 보드, 흑/백 턴, 착수, 승패·무승부·기권 | OpenRouter/LLM 호출 (Step 2) |
| 규칙 엔진(자유룰) + 단위 테스트 | 수별 분석·색상 복기 (Step 2·3) |
| AI 난이도 하/중/상 (Web Worker) | 기보 보관함·전적·프로필 (Step 3) |
| 2인 로컬 대전 | 온라인 대전, 계정 로그인 |
| GameRecord 생성(메모리 상 보관) | 영구 저장 (Step 3) |
| (P2) 렌주룰 옵션, 무르기 | 효과음·BGM |

## 1. 구현 내용

### 1.1 프로젝트 초기 설정 (P0)

- Vite + React(JavaScript, ES Modules) 프로젝트 생성. 디렉터리는 `docs/00_PLANNING_5W1H.md §5` 구조를 따른다.
- 의존성은 최소화: `react`, `react-dom`, 개발용 `vite`, `vitest`, `concurrently`(서버는 Step 2부터). **차트·UI 라이브러리 추가 금지.**
- `package.json` 스크립트: `dev`(클라이언트), `build`, `test`, `selfplay`(AI vs AI).
- `.gitignore`에 `.env`, `node_modules`, `dist` 포함. `.env.example` 생성(키 이름만, 값은 비움).
- `src/styles/tokens.css`에 디자인 토큰 정의(§1.8). 복기용 분류 색상 토큰도 **지금 미리** 정의한다(Step 3에서 재사용).
- 화면 전환은 상태 기반(별도 라우터 라이브러리 없음): `home → game → (result modal)`.

### 1.2 엔진 코어 — `src/engine/` (P0)

**DOM·React에 의존하지 않는 순수 함수**로 작성한다. 모든 함수는 단위 테스트 대상이다.

```js
// 상수
EMPTY = 0, BLACK = 1, WHITE = 2, SIZE = 15
// 보드: Uint8Array(SIZE*SIZE), 인덱스 = y*SIZE + x  (좌상단 원점, 0-index)
```

| 모듈 | 함수 | 설명 |
|---|---|---|
| `board.js` | `createBoard()`, `idx(x,y)`, `inRange(x,y)` | 보드 생성·인덱스 |
| | `toLabel(x,y)` → `"H8"`, `fromLabel("H8")` → `{x,y}` | **좌표 변환은 이 두 함수만** 사용 (`GAME_RULES.md §5`) |
| | `placeStone(state, x, y)` → `{ ok, state } \| { ok:false, code }` | 불변(immutable) 갱신. 실패 코드: `OUT_OF_RANGE`, `OCCUPIED`, `GAME_OVER`, `FORBIDDEN` |
| `rules.js` | `checkWin(board, x, y, color, ruleset)` → `{ win, line }` | 마지막 수 기준 4방향 스캔. `line`은 승리 구간 좌표 배열 |
| | `isDraw(movesCount)` | 225수 도달 && 승자 없음 |
| | `getLegalMoves(state)` | 빈 칸(렌주룰이면 금수 제외) |
| `patterns.js` | `analyzeLine(board, x, y, color, dir)` | 연속 길이·양끝 열림 여부 → 2/3/4/열린3/열린4 분류. Step 2 분석에서 재사용 |

**GameState / GameRecord 구조 (고정 스키마):**

```jsonc
{
  "version": 1,
  "id": "g_20261001_a1b2",
  "createdAt": "2026-10-01T09:00:00.000Z",
  "boardSize": 15,
  "ruleset": "free",                 // "free" | "renju"
  "mode": "pve",                     // "pve" | "pvp"
  "difficulty": "normal",            // "easy" | "normal" | "hard" | null(pvp)
  "players": {
    "black": { "type": "human", "name": "플레이어" },
    "white": { "type": "ai",    "name": "AI(중)" }
  },
  "moves": [ { "n": 1, "color": "B", "x": 7, "y": 7 } ],   // n은 1부터
  "result": {
    "winner": "B",                   // "B" | "W" | "draw"
    "reason": "five",                // "five" | "resign" | "board_full"
    "winLine": [[3,7],[4,7],[5,7],[6,7],[7,7]],
    "totalMoves": 23
  }
}
```

### 1.3 대국 모드·시작 화면 (P0)

시작 화면(`ModeSelect`)에서 선택:

1. **대국 방식**: `AI와 두기(PvE)` / `둘이서 두기(PvP)`
2. **난이도**(PvE만): `하 / 중 / 상` — 각각 한 줄 설명 표시(예: "하: 입문자용, 가끔 실수해요")
3. **내 돌 색**: `흑(선공)` / `백(후공)` / `랜덤`
4. **규칙**: `자유룰(기본)` / `렌주룰(금수 적용)` — 렌주룰은 P2 구현 전까지 비활성 + "준비 중" 표기
5. **닉네임**: 기본값 `플레이어` (최대 12자)

[대국 시작] 버튼 → 게임 화면.

### 1.4 보드 UI (P0)

- **SVG 렌더링**(권장) 또는 CSS Grid. 15×15 격자선, 화점 5개, 외곽 여백에 좌표 라벨(`A`~`O` / `1`~`15`).
- 호버 시 둘 수 있는 교점에 **반투명 미리보기 돌**. 이미 돌이 있는 곳은 커서 `not-allowed`.
- 클릭/탭 → 착수. 돌이 놓일 때 120ms scale-in 애니메이션.
- **마지막 수 표시**: 돌 위에 작은 점(또는 링). 토글로 **수 번호 표시** 켜기/끄기.
- 승리 시 **5목 구간 하이라이트**(선 + 돌 글로우).
- 반응형: 보드는 화면 너비에 맞춰 정사각형 유지(최소 320px). 모바일에서 교점 터치 영역 ≥ 24px.
- 접근성: 보드에 `aria-label`, 현재 차례를 텍스트로도 표시(색만으로 구분하지 않음).

### 1.5 대국 HUD (P0)

- 상단: 양 플레이어 카드(닉네임, 돌 색, **현재 차례 강조**), 현재 수 번호, 경과 시간.
- 하단: [기권] [수 번호 보기 토글] [처음으로]. 기권은 확인 다이얼로그 후 처리.
- PvE에서 AI 차례에는 "AI가 생각 중…" 표시, **보드 입력 잠금**.

### 1.6 AI 난이도 — `engine/ai.js`, `engine/search.js`, `workers/aiWorker.js` (P0)

AI는 **Web Worker**에서 실행해 UI 멈춤을 방지한다. 메인 스레드는 `{ board, color, difficulty }`를 보내고 `{ x, y, meta }`를 받는다. (LLM 사용 금지)

**후보 수 생성:** 기존 돌에서 반경 R 이내의 빈 칸만 후보(첫 수 제외). 판이 비어 있으면 천원 `(7,7)`, AI 백이면 흑 첫 수 인접 칸.

**평가 함수 (`evaluate.js`, 참고 점수표 — 튜닝 가능, 값은 `constants/config.js`):**

| 패턴 | 점수 |
|---|---|
| 5목 | 1,000,000 |
| 열린 4 | 100,000 |
| 막힌 4 | 10,000 |
| 열린 3 | 5,000 |
| 막힌 3 | 500 |
| 열린 2 | 300 |
| 막힌 2 | 30 |

한 칸의 점수 = `공격점수(내 돌이 되었을 때) × 공격가중 + 수비점수(상대 돌이 되었을 때) × 수비가중`.

**난이도 정의 (`constants/config.js`의 `DIFFICULTY`에 그대로 반영):**

| 항목 | 하 (easy) | 중 (normal) | 상 (hard) |
|---|---|---|---|
| 알고리즘 | 1수 휴리스틱 + 확률적 선택 | 1수 휴리스틱 + 상대 응수 1수 확인 | alpha-beta, 반복 심화(깊이 2→4), 위협 우선 정렬 |
| 후보 반경 | 1 | 2 | 2 (상위 12개만 탐색) |
| 공격 : 수비 가중 | 1.0 : 0.6 | 1.0 : 1.0 | 1.0 : 1.2 |
| 내 5목 완성 수행 | 90% | 100% | 100% |
| 상대 막힌 4 차단 | 85% | 100% | 100% |
| 상대 열린 3 차단 | 40% | 85% | 탐색에 위임 |
| 최종 선택 | 상위 6개 중 점수 가중 무작위 | 상위 2개 중 70/30 | 최선 수 고정(동점 시 중앙에 가까운 칸) |
| 응답 목표 | ≤ 300ms | ≤ 500ms | ≤ 2초 (초과 시 그때까지의 최선 수) |

- 모든 난이도에서 **AI의 수는 항상 합법 수**여야 한다(점유 칸·판 밖 금지). Worker 오류/타임아웃 시 **합법 수 중 평가 최고 칸**으로 대체하고 콘솔 경고.
- 자연스러운 템포를 위해 AI 응답 표시는 **최소 400ms 지연**.
- 난이도 순서 검증: `npm run selfplay`(100판, 흑백 교대) 결과가 아래 **목표**를 만족해야 한다(미달 시 가중치·확률 튜닝).
  - 중 vs 하: 중 승률 ≥ 75% / 상 vs 중: 상 승률 ≥ 70% / 상 vs 하: 상 승률 ≥ 90% (무승부 제외)

### 1.7 승패 처리·결과 화면 (P0)

- 5목 완성 즉시 대국 종료 → 입력 잠금 → 5목 하이라이트 → 0.8초 후 **결과 모달**.
- 결과 모달: 승자(색+닉네임), 총 수, 소요 시간, 사유(5목/기권/무승부).
- 버튼: **[AI 복기]**(Step 1에서는 비활성, "2단계에서 활성화" 툴팁) · [같은 설정으로 다시] · [설정 바꾸기] · [홈으로].
- 종료 시 **GameRecord 생성**(1.2 스키마) 후 앱 상태에 보관. `window.__lastGame`(개발 모드 한정)으로 콘솔에서 확인 가능하게 노출.

### 1.9 에러·예외 처리 (P0)

### 1.10 옵션 기능 (P2 — 핵심 완료 후 진행)

- **렌주룰**: 흑 삼삼·사사·장목 금수 판정(`rules.js` + `patterns.js`), 금수 클릭 시 "금수입니다(삼삼/사사/장목)" 안내, 금수 칸 보드에 ✕ 힌트 표시. 엣지 케이스는 `GAME_RULES.md §6` 참조.
- **무르기**: PvE에서 2수 되돌리기, 대국당 3회, 기보에서 제거.
- **다크 모드**.

## 2. 구현 순서 (바이브 코딩 권장 순서)

1. 프로젝트 세팅 + `tokens.css` + 빈 화면 라우팅
2. `engine/board.js`, `rules.js` + **단위 테스트 먼저**(`tests/rules.test.js`) → 전부 통과
3. 보드 UI + PvP 대국 + 결과 모달 (여기까지가 "2인 대전 완성")
4. `evaluate.js` + `ai.js`(하/중) + Worker 연동 → PvE 하/중 동작
5. `search.js`(상) + 시간 제한 + 폴백
6. `scripts/selfplay.js`로 난이도 검증·튜닝
7. 시작 화면·HUD·접근성·반응형 다듬기
8. (P2) 렌주룰 / 무르기 / 다크 모드

각 단계가 끝날 때마다 `npm test`와 수동 실행으로 확인하고, 통과 전에는 다음으로 넘어가지 않는다.

## 3. 수락 기준 (Acceptance Criteria)

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-1-01 | 15×15 보드가 표시되고 클릭으로 흑·백이 번갈아 착수된다 | 수동 |
| AC-1-02 | 가로·세로·↘·↗ 5목 즉시 승리, 4목은 승리가 아니다 | 자동 `rules.test.js` |
| AC-1-03 | 경계(네 모서리·가장자리)에서도 승리 판정이 정확하다 | 자동 |
| AC-1-04 | 마지막 돌이 5목의 **가운데/끝**일 때 모두 승리로 판정된다 | 자동 |
| AC-1-05 | 점유 칸·판 밖 착수는 거부되고 상태가 변하지 않는다 | 자동 |
| AC-1-06 | 225수가 차면 무승부, 단 마지막 수가 5목이면 승리 | 자동 |
| AC-1-07 | `toLabel/fromLabel`이 서로 역변환이며 `(7,7)=H8`, `(0,0)=A1`, `(14,14)=O15` | 자동 |
| AC-1-08 | AI(하/중/상)는 어떤 국면에서도 합법 수만 둔다 (랜덤 국면 1,000개) | 자동 `ai.test.js` |
| AC-1-09 | 내가 3수 안에 5목을 만들 수 있게 **막힌 4를 방치**하면 중·상 AI는 즉시 승리 수를 둔다 | 자동 |
| AC-1-10 | 상대 막힌 4가 생기면 중·상 AI는 항상 차단한다 | 자동 |
| AC-1-11 | `selfplay` 승률이 §1.6 목표를 만족한다 | 스크립트 |
| AC-1-12 | 상 난이도 AI 응답이 2초를 넘지 않고, 그동안 UI가 멈추지 않는다 | 수동+측정 |
| AC-1-13 | 종료 후 GameRecord가 스키마(§1.2)에 맞게 생성되고 `moves` 수 = `totalMoves` | 자동 |
| AC-1-14 | [다시]/[홈으로] 후 보드·턴·타이머·기보가 완전히 초기화된다 | 수동+자동 |
| AC-1-15 | 모바일(360px)에서 보드 전체가 보이고 터치로 정확히 착수된다 | 수동 |

## 4. 테스트 시나리오 (구현 후 `메인 애플리케이션을 실행해서 1단계 결과 테스트`)

1. **PvP 빠른 승부**: 흑이 가로로 5목 → 결과 모달에 흑 승, 5목 하이라이트, 총 9수 확인
2. **PvE 하**: 의도적으로 열린 3을 만들어 AI가 막지 않는 경우가 있는지 3판 관찰(하는 가끔 놓쳐야 함)
3. **PvE 중/상**: 같은 전략으로 두면 AI가 방어하는지 확인, 상은 반격(4-3 시도)하는지 관찰
4. **기권**: 대국 중 기권 → 사유 `resign`, 승자 상대
5. **무승부 유도**: (테스트 픽스처로) 224수가 찬 국면 로드 → 마지막 수 → 무승부/승리 구분
6. **새로 시작**: 결과 후 [같은 설정으로 다시] → 수 번호 1부터, 타이머 0
