# PRD STEP 03 — 색상 복기 뷰어 + 기보 보관함·프로필 + 안정화

> 선행 조건: Step 2 완료(`ReviewResult` 생성 가능). 선행 문서: `CLAUDE.md`, `docs/VALIDATION_GUIDELINES.md`

## 목표

복기 결과를 **한눈에 읽히는 시각 경험**으로 만든다. 사용자가 수별 평가를 **색으로 훑어보고**, **승부처(★)만 골라 보고**, 최선 수를 판 위에서 확인하며 복기할 수 있어야 한다. 또한 대국 기록을 **내 프로필의 보관함**에 저장해 전적과 함께 다시 볼 수 있게 하고, 시연 가능한 수준으로 안정화한다.

## 범위

| 포함 (In) | 제외 (Out) |
|---|---|
| 복기 뷰어: 보드·타임라인·승률 그래프·상세 패널·필터·범례 | 서버 DB, 로그인/계정 |
| 수별 5단계 색상 + ★ 결정적 수 시각화 | 온라인 공유 링크 |
| 프로필(닉네임·아바타 색), 기보 보관함, 전적 통계 | 실시간 멀티플레이 |
| localStorage 저장·내보내기/가져오기 | 모바일 앱 패키징 |
| 데모 모드(사전 계산 기보 + 복기 결과) | |
| 안정화: 상태 초기화·오류·반응형·접근성, README | |

## 1. 구현 내용

### 1.1 복기 화면 레이아웃 (P0)

```
┌──────────────────────────────────────────────────────────────┐
│ ← 보관함   복기: 플레이어(흑) vs AI(중)   [흑 승 · 23수]       │
├───────────────────────────────┬──────────────────────────────┤
│                               │ 총평 카드 (headline · 강점/약점/팁) │
│        복기 보드               │ ─────────────────────────── │
│        (현재 수까지)           │ 승부처 ★ 요약 (클릭 이동)       │
│                               │ ─────────────────────────── │
│                               │ 선택한 수 상세 패널             │
├───────────────────────────────┴──────────────────────────────┤
│ 필터바  [전체][★승부처][실착·패착][흑][백]      범례 ◎ ○ · △ ✕ ★ │
│ 승률 그래프 (흑 기준, 클릭하면 해당 수로 이동)                   │
│ 타임라인 스트립 (1 … N, 분류 색 칩)   |< < ▶ > >|  ━━●━━ 슬라이더 │
```

- 모바일(<768px): 보드 → 컨트롤 → 탭(`타임라인 / 그래프 / 해설 / 요약`) 세로 배치.
- 진입 시 기본 상태: **마지막 수가 아니라 첫 ★ 결정적 수**를 선택해 "여기부터 보세요" 경험을 준다. (전체 보기는 |< 로 이동)

### 1.2 색상·기호 체계 (P0 — 이 표가 시각화의 단일 기준)

색만으로 구분하지 않는다. **색 + 기호 + 텍스트 라벨**을 항상 함께 쓴다(색각 이상 대응).

| 분류 | 라벨 | 기호 | 라이트 색 | 의미 | 기준(Step 2) |
|---|---|---|---|---|---|
| `best` | 최선 | ◎ | `#0A84FF` 파랑 | 엔진 1순위 또는 거의 동급 | loss ≤ 2%p |
| `good` | 좋음 | ○ | `#30B15A` 초록 | 충분히 좋은 수 | ≤ 5%p |
| `ok` | 보통 | · | `#8E8E93` 회색 | 무난, 큰 영향 없음 | ≤ 10%p |
| `mistake` | 실착 | △ | `#FF9F0A` 주황 | 아쉬운 수 | ≤ 20%p |
| `blunder` | 패착 | ✕ | `#FF3B30` 빨강 | 승부에 치명적 | > 20%p 또는 하드 규칙 |
| `key` | 결정적 수 | ★ | `#FFD60A` 금색 + 어두운 외곽선 | 승부처 (분류와 별개로 중첩 표시) | `isKey` |

- 토큰은 Step 1 `tokens.css`의 `--c-*`를 그대로 사용. 다크 모드는 채도를 올린 변형을 토큰에서만 교체.
- 텍스트 위 배지는 **WCAG AA 대비(4.5:1)** 이상.
- `src/constants/colors.js`에 분류별 `{ label, symbol, cssVar }` 매핑을 두고, **모든 컴포넌트가 이 매핑만 참조**한다(하드코딩 금지).

### 1.3 복기 보드 — `ReviewBoard.jsx` (P0)

- 선택한 수 `k`까지의 돌만 표시. 돌 위에 **수 번호**, 돌 바깥에 **분류 색 링**(토글: `분류 링 표시`).
- 현재 수는 두꺼운 링 + 약한 펄스. ★ 수는 금색 별 배지.
- **최선 수 표시:** 선택한 수에서 엔진 추천(`bestAlt`)을 판 위에 **점선 원 + 라벨**로 표시(1순위 진하게, 2·3순위 흐리게). 실제로 둔 수와 같으면 "최선과 일치" 표시.
- 마지막 수(승리 수)에서는 5목 구간 하이라이트.
- Step 1의 `Board`/`Stone` 렌더링을 재사용하되 읽기 전용(클릭 착수 비활성).

### 1.4 컨트롤·내비게이션 (P0)

- 버튼: `|<` 처음 · `<` 이전 · `▶/⏸` 자동재생(1× / 2×) · `>` 다음 · `>|` 끝
- 슬라이더(0…N), **[이전 ★] [다음 ★]** 버튼(결정적 수 간 점프)
- 키보드: `←`/`→` 이전/다음, `Home`/`End`, `Space` 재생/정지, `[`/`]` 이전/다음 ★
- **필터가 켜져 있으면 `<` `>` 및 `[` `]`는 필터에 해당하는 수 사이에서만 이동**한다.

### 1.5 타임라인 스트립 — `MoveTimeline.jsx` (P0)

- 1…N 칩을 가로로 나열(길면 가로 스크롤, 현재 수 자동 중앙 정렬). 칩 배경 = 분류 색, 칩 안 = 기호 + 수 번호.
- 흑/백 구분: 칩 상단(흑)·하단(백) 2줄 레이아웃 **또는** 칩 모서리의 ●/○ 마크.
- ★ 칩은 금색 외곽선 + 별.
- 호버/롱프레스 툴팁: `17수 · 백 I7 · 패착 · 승률 48% → 81%`.
- 필터에 해당하지 않는 칩은 투명도 30%로 흐리게(숨기지 않음).

### 1.6 승률 그래프 — `WinRateChart.jsx` (P0)

- **SVG 직접 렌더**(차트 라이브러리 금지). x = 수 번호, y = 흑 승률(0~100%), 50% 기준선.
- 선은 부드럽게, 선 아래는 흑(위)/백(아래) 우세 영역을 옅게 채색.
- 각 수에 점 표시: 점 색 = 분류 색, ★은 별 마커. 현재 수에 세로 가이드선.
- 그래프 클릭/드래그 → 해당 수로 이동. 급락·급등 구간은 자연스럽게 눈에 띈다.
- 접근성: `<title>`/`aria-label`로 요약 문장("흑이 12수부터 우세, 17수에서 역전").

### 1.7 필터·한눈에 보기 (P0)

- 필터바: `전체` · `★ 승부처` · `실착·패착` · `흑` · `백` (색 필터는 AND 조합 가능: 예 `백` + `실착·패착`)
- **승부처 요약 카드:** ★ 수 목록(수 번호, 색, 좌표, 분류 배지, 한 줄 해설). 클릭 시 해당 수로 이동·보드 강조.
- 범례(`Legend.jsx`): §1.2 표 그대로(기호·색·라벨·기준 한 줄). 항상 접근 가능(모바일은 `?` 팝오버).

### 1.8 수 상세 패널 — `MoveDetailPanel.jsx` (P0)

선택한 수의 정보를 위에서 아래 순으로:

1. 제목: `17수 · 백 · I7` + 분류 배지 + ★
2. 승률 변화 막대: `48% → 81%` (흑 기준) 와 `이 수로 −31%p` 같은 손실 문구
3. 엔진 태그 칩(한글 라벨 매핑: 예 `MISSED_BLOCK` → "상대 4 방치")
4. **추천 수 Top 3:** 좌표 + 예상 승률 (클릭하면 보드에 해당 위치 강조)
5. 해설 텍스트 + 출처 배지(`AI 해설` / `엔진 해설`)
6. (P2) **[다른 수 두면?]**: 추천 1순위 돌을 임시로 올려 보드에 보여주기(저장 없음)

### 1.9 요약 대시보드 — `SummaryCard.jsx` (P1)

- 색상별 개수 막대(흑·백 나란히), **정확도**(최선+좋음 비율), 평균 손실(%p)
- LLM 총평 카드(headline / 강점 / 약점 / 팁). 총평이 템플릿이면 배지 표시.
- "이번 판의 승부처" 문장 1줄(예: "17수에서 흐름이 바뀌었어요").

### 1.10 프로필 & 기보 보관함 (P0/P1)

| 기능 | 내용 | 우선순위 |
|---|---|---|
| 프로필 | 닉네임, 아바타 색(8색 팔레트). 첫 실행 시 간단 생성 → `localStorage` | P0 |
| 자동 저장 | 대국 종료 시 `GameRecord` 저장, 복기 완료 시 `ReviewResult` 연결 | P0 |
| 보관함 목록 | 카드: 날짜 · 모드/난이도 · 결과 · 수 · 복기 여부 배지 · 정확도. 정렬(최신/정확도), 필터(난이도/결과) | P0 |
| 열기 | 복기 완료 기보는 **API 재호출 없이** 바로 뷰어 오픈, 미복기는 [AI 복기] 실행 | P0 |
| 삭제 | 개별 삭제(확인), 전체 삭제 | P1 |
| 전적 | 난이도별 승/무/패, 승률, 최장 연승, 평균 정확도, 최단 승리 수 | P1 |
| 내보내기/가져오기 | JSON 파일로 기보(+복기) 백업/복원, 스키마 버전 검증 | P1 |
| 이어하기 | 진행 중 대국을 `localStorage`에 자동 저장 → 새로고침 후 "이어하기" | P2 |

**저장소 규칙 (`services/storage.js`):**
- 키: `omok:profile`, `omok:games:index`, `omok:game:{id}`, `omok:review:{id}`, `omok:settings`
- **모든 읽기/쓰기는 try/catch**, 실패(용량·차단) 시 앱은 계속 동작하고 "저장하지 못했어요" 토스트만 표시.
- 보관 한도 **200판**(초과 시 가장 오래된 것부터 정리, 사용자에게 안내). 저장 데이터에 `version` 필드 포함, 읽을 때 버전 검사·마이그레이션 훅.
- 파싱 실패한 항목은 건너뛰고 나머지를 정상 표시(전체 크래시 금지).

### 1.11 데모 모드 (P0 — 발표/시연용)

- `public/demo-games/`에 **기보 3개 + 사전 계산된 `ReviewResult`**(실제 LLM 해설 포함) 내장: ① 짧은 승부 ② 역전 승부 ③ 장기전.
- 홈 화면 [데모 복기 보기] → 네트워크·API 키 없이 즉시 뷰어 오픈.

| AC-3-15 | `/omok-validate all` 결과 ❌ 0건 | 명령 |

## 4. 테스트 시나리오 (구현 후 `메인 애플리케이션을 실행해서 3단계 결과 테스트`)

1. **데모 복기**: 홈 → [데모 복기] → 역전 승부 열기 → 그래프의 급락 지점 클릭 → 해당 수가 ★/패착인지, 추천 수가 판에 보이는지
2. **필터 조합**: `백` + `실착·패착` → 타임라인에서 해당 칩만 선명한지, `>` 이동이 그 수들 사이만 가는지
3. **실제 대국 → 복기 → 저장**: 중 난이도로 대국 → 승패 후 [AI 복기] → 색상 뷰어 → 보관함에 카드 생성 → 새로고침 후에도 유지
4. **오프라인**: 서버 중지 상태에서 이미 복기된 기보 열기(정상), 미복기 기보 [AI 복기](엔진 해설로 완료 + 안내)
5. **백업/복원**: 내보내기 → 전체 삭제 → 가져오기 → 전적 수치 동일
6. **접근성/반응형**: 키보드 전용 조작, 360px 에뮬레이션
